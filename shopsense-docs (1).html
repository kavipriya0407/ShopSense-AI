Technical overview

How ShopSense AI is built, and how data moves through it

A multi-role commerce platform — storefront, vendor hub and admin console — wired to a retrieval-augmented shopping assistant and data analyst. This page maps the system end to end: architecture, the three user journeys, the API surface, and how to run it locally.

3user roles: buyer, vendor, admin
2RAG endpoints: assistant & analyst
4Postgres tables, with in-memory fallback
28+routed pages across the app

System design

Architecture at a glance

One Vite/React frontend serves all three roles behind client-side routing. A single Express API exposes health, database status, and the two RAG endpoints, backed by PostgreSQL with an in-memory dataset as a fallback when no database is reachable.

Backend surface

API reference

Four endpoints cover the whole backend today: two for health and status, two that front the RAG assistant and analyst.

MethodEndpointDescription
GET/api/healthService health check
GET/api/db/statusReports whether PostgreSQL or the in-memory fallback is active
POST/api/rag/assistantRAG shopping assistant — body: { query, filters }
POST/api/rag/analystRAG data analyst — body: { query, dateRange }

Local setup

Getting started

Install dependencies

Frontend and backend have separate package files.

npm install
cd server && npm install && cd ..

Set environment variables

Create a .env with a database connection string; the app falls back to an in-memory dataset if it can't connect.

DATABASE_URL=postgres://postgres:postgres@localhost:5432/shopsense
PORT=5000

Apply the schema (optional)

Skip this if you're running on the in-memory fallback.

createdb shopsense
psql -d shopsense -f server/db/schema.sql

Run both servers

The API and the frontend run separately, in two terminals.

npm run server   # http://localhost:5000
npm run dev      # http://localhost:5173
